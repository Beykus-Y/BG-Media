# BG Vox — Enhance MVP (P1)

Статус: P1 «BG Vox Enhance» из issue #82. Отдельная, независимо собираемая и
отключаемая библиотека `bgmedia_vox` (`BGMedia::Vox`). Не зависит от
`bgmedia_core`, не знает про Telegram/TDLib, микрофон, Opus и UI.

## 1. Что входит в этот PR

- Офлайн-обработка **уже записанного** голосового PCM после остановки записи
  (post-recording): шумоподавление, мягкая компрессия, нормализация громкости,
  лимитер.
- Публичный C++ API `bgmedia::vox` (`include/bgmedia/vox/VoxEnhance.hpp`) и C ABI
  для будущих JNI/iOS-хостов (`include/bgmedia/vox/vox_capi.h`).
- Инструмент `bgmedia_vox_enhance` для слепого A/B-прослушивания и измерений.
- Unit-тесты `vox.*` на синтетических сигналах (без внешних фикстур).

Сборка: опция `BGMEDIA_BUILD_VOX` (по умолчанию `ON`). Библиотека не линкует
`bgmedia_core`, компилирует собственную копию KissFFT (цель
`bgmedia_vox_kissfft`) с префиксом символов `bgvox_`, поэтому core и vox можно
линковать в один бинарник или одну shared-библиотеку без дублей символов. При `-DBGMEDIA_BUILD_VOX=OFF` проект
собирается без изменений, цель `bgmedia.vox` и инструмент не создаются.

## 2. Что НЕ сделано

- **Аудит и интеграция в BeyGram Android.** Исходники BeyGram недоступны в этом
  репозитории, поэтому никаких утверждений о его аудиотракте здесь нет. Аудит и
  подключение — отдельный PR в BeyGram `dev` после согласования контракта
  (раздел 8).
- **P2 Transcribe** — сделан отдельным PR, см. [BG_VOX_TRANSCRIBE.md](BG_VOX_TRANSCRIBE.md)
  (офлайн-распознавание речи, опциональный адаптер whisper.cpp, аудит
  whisper.cpp vs sherpa-onnx). **P3 Lyrics** — сделан отдельным PR, см. [BG_VOX_LYRICS.md](BG_VOX_LYRICS.md)
  (текст провайдера от хоста, LRC, вокальные участки, выравнивание, происхождение
  строк). **P4** — не начат.
- Live-режим (обработка во время записи) не реализован и не заявляется как лучший
  вариант: его нужно отдельно измерять (раздел 7).
- Нейросетевые бэкенды (RNNoise, DeepFilterNet) не вендорятся (раздел 9).

## 3. Цепочка DSP

Порядок строго такой; все стадии работают in-place на interleaved `float` PCM.
Для стерео анализ идёт по среднему каналов, а **все коэффициенты усиления
(denoise, компрессор, makeup, лимитер) одинаковы для обоих каналов** — стереообраз
не меняется.

| # | Стадия | Natural | Strong (experimental) |
|---|--------|---------|-----------------------|
| 1 | DC + high-pass, Butterworth 2-го порядка (RBJ), double-состояние | 80 Гц | 100 Гц |
| 2 | Спектральное шумоподавление (STFT sqrt-Hann, 50 % overlap, окно ≈ 32 мс: 256 @ 8 кГц, 512 @ 16 кГц, 1024 @ 32/44.1/48 кГц) | floor −12 дБ | floor −20 дБ, оценка шума ×1.4 |
| 3 | VAD по энергии (кадры 10 мс, порог = 10-й перцентиль + 9 дБ и не ниже −62 дБFS, отбрасывание всплесков < 30 мс, hangover) | 200 мс | 200 мс |
| 4 | Компрессор: feed-forward RMS, soft knee 6 дБ, порог −24 дБFS, attack 10 мс, release 150 мс, без makeup | 2:1 | 3:1 |
| 5 | Нормализация: один статический gain по RMS речевых (VAD) кадров | цель −20 дБFS, [−6; +12] дБ | цель −18 дБFS, [−6; +15] дБ |
| 6 | Лимитер: lookahead 5 мс, release 50 мс, потолок −1 дБFS, затем финальный clamp | −1 дБFS | −1 дБFS |
| 7 | Quality guard | RMS речи на выходе не ниже входного −20 дБ, выход конечный | то же |

Детали шумоподавления (внутренний интерфейс `IVoxDenoiser`,
`src/vox/VoxDenoiser.hpp`):

- Оценка PSD шума — упрощённая minimum statistics: сглаженная периодограмма
  (α = 0.9, лёгкое 3-бинное сглаживание по частоте), минимум по 4 под-окнам общей
  длиной ≈ 1.5 с, компенсация смещения ×1.7. Начальное значение берётся из самого
  тихого участка записи (≈ 0.3 с), поэтому оценка не требует 1.5 с «разгона».
  Если этот участок не тише медианы хотя бы на 3 дБ (короткое сообщение или
  речь без пауз), ему не доверяют: старт идёт на 10 дБ ниже, иначе сама речь
  ушла бы в пол подавления.
- Усиление: decision-directed a-priori SNR (α = 0.98), Wiener gain, нижний порог
  (floor) по режиму; сглаживание по частоте (3 бина) и по времени
  (асимметрично: рост быстро, падение медленнее) против «музыкального шума».
- Задержка STFT компенсируется структурой кадрирования (первый кадр начинается на
  −hop, хвост достраивается нулями): выход выровнен с входом сэмпл-в-сэмпл; при
  gain = 1 STFT восстанавливает вход (тест: ошибка < 1e-4).
- Нет речи → makeup 0 дБ: тишина и шум не усиливаются.

Альтернативный бэкенд (RNNoise и т. п.) реализует `IVoxDenoiser::process()`
(in-place, interleaved, выровнен по времени); встроенный остаётся по умолчанию.

## 4. Fail-open и коды статуса

`enhanceVoice()` — `noexcept`, перехватывает `std::bad_alloc` и любые исключения.
При любой проблеме результат содержит **исходные сэмплы** (копия, как `float`) и
статус причины. Длина, число каналов и частота результата всегда равны входным.

| Код | Статус | Когда |
|-----|--------|-------|
| 0 | `Processed` | обработано |
| 1 | `Bypassed` | режим `Off` — бит-в-бит оригинал |
| 2 | `FallbackUnsupportedFormat` | частота вне 8000..48000 Гц или каналов не 1/2 |
| 3 | `FallbackTooLong` | длительность > `maxDurationSeconds` (по умолчанию 600 с) |
| 4 | `FallbackOutOfMemory` | не хватило памяти (буферы резервируются до начала обработки; если не удалось даже скопировать оригинал, `pcm` пуст) |
| 5 | `FallbackInternalError` | неожиданное исключение |
| 6 | `FallbackQualityGuard` | речь «уничтожена» (−20 дБ и больше) или выход не конечный |
| 7 | `Cancelled` | сработал `VoxCancelToken` |
| 8 | `FallbackInvalidInput` | null-указатель, `frames == 0`, NaN/Inf во входе (добавлен к списку из issue) |

`Off` проверяется первым: даже при нестандартном формате возвращается копия
оригинала со статусом `Bypassed`. `usedOriginal()` истинно для всех статусов,
кроме `Processed`. int16-вход конвертируется точно (`x / 32768.0f`), обратная
`toInt16()` округляет и ограничивает; для значений, пришедших из int16, цикл
точный.

## 5. Потоки, владение PCM, память

- Вызывающий владеет входным буфером на время вызова; результат владеет своим
  буфером. Вызов блокирующий, без глобального состояния и локов; допустим
  параллельный вызов на разных буферах (тест: 4 потока дают результат,
  побитово равный однопоточному). Детерминирован.
- **Не** для realtime-потока: не вызывать из audio/capture callback.
  Обработку запускать в рабочем потоке хоста.
- Отмена: `VoxCancelToken::cancel()` из любого потока; проверяется на каждом
  STFT-кадре и каждые ~8192 сэмплов в остальных стадиях. В C ABI —
  `const volatile int* cancel_flag`.
- Прогресс: `VoxProgressFn(float)` вызывается примерно каждые 5 % (монотонно,
  последний вызов — 1.0) из потока обработки; ни один внутренний лок не держится
  (локов нет).
- Память — O(frames): float-путь ≈ 1 × (frames × channels × 4 Б) для результата
  + малые вспомогательные буферы (< 1 МБ + 4 Б × frames / (rate/100) для VAD).
  Обработка идёт in-place в буфере результата. int16-путь добавляет временную
  float-копию (≈ 2 ×). Примеры для максимума 600 с: 16 кГц моно ≈ 38 МБ
  (float) / 77 МБ (int16); 48 кГц стерео ≈ 230 МБ / 460 МБ. Для голосовых
  сообщений мессенджера (минуты, 16–48 кГц моно) — единицы мегабайт.

## 6. Почему сначала post-recording

- Запись завершена, поэтому доступны два прохода: статическая нормализация по
  RMS речи по всему сообщению, начальная оценка шума по самому тихому месту.
- Нет риска для capture-потока и задержек записи; сбой обработки не влияет на
  уже записанный оригинал (fail-open).
- Быстро: ≈ 700–1000× realtime на настольной машине (раздел 10).

## 7. Live-режим

Не реализован. Утверждения, что live лучше или хуже, не делаются: потребуются
замеры на устройстве (задержка, нагрузка CPU, качество без двухпроходной
нормализации). Решение — после P1 на реальных данных.

## 8. Контракт интеграции для хоста

Хост (BeyGram Android) владеет захватом, Opus-кодированием, UI и отправкой.
BG Vox получает только PCM.

1. После остановки записи хост передаёт в `enhanceVoice()` (или
   `bgm_vox_enhance_s16`) весь PCM: частота 8000–48000 Гц, 1–2 канала.
2. Режимы: `Off` (по умолчанию), `Natural`, `StrongExperimental` (явно помечен
   экспериментальным).
3. Хост **хранит оригинал** до отправки или отмены и не удаляет его при любом
   статусе, кроме `Processed`; при `usedOriginal()` кодирует то, что вернулось
   (это и есть оригинал).
4. A/B-прослушивание (оригинал против обработанного) и переключение режимов —
   UX хоста; библиотека обрабатывает каждый режим независимо и не хранит состояния.
5. Обработка в рабочем потоке, не в capture/audio callback; отмена по
   нажатию пользователя через токен/флаг.
6. Opus-кодирование результата — на стороне хоста (в `Processed` пик ≤ −1 дБFS,
   запас против intersample-пиков кодека).

## 9. Заметки по RNNoise и DeepFilterNet

- **RNNoise** (BSD-3-Clause): 48 кГц, моно, кадры 480 сэмплов (10 мс), небольшая
  встроенная модель (порядка 85 КБ весов), GRU. Для путей 16 кГц нужен
  ресемплинг. Кандидат на бэкенд через `IVoxDenoiser`; в этот PR не вендорится
  (лицензия и размер модели оценить отдельно, сравнить A/B со встроенным).
- **DeepFilterNet** (MIT/Apache-2.0): качественнее, но заметно тяжелее по CPU и
  зависимостям; рассматривается позже и только как опциональный адаптер.

## 10. Измерения

### Десктоп (синтетика, `bgmedia_vox_enhance --synthetic`)

Release, GCC, Linux x86-64, один поток. Сигналы: 20 с, 16 кГц моно,
«речеподобные» слова + шум. `pauseSNR` — уровень внутри слов минус уровень
внутри пауз (дБ; независим от общего gain). `corr` — корреляция с чистой речью
(занижается сдвигом фазы high-pass). xRT — во сколько раз быстрее realtime.

## 11. План приёмки (из issue #82)

1. Записи на реальных устройствах: тихая комната, улица, вентилятор/кондиционер,
   клавиатура, далёкий микрофон, стерео-микрофон, гарнитура; разные языки и
   дикторы.
2. Слепое A/B (`bgmedia_vox_enhance in.wav prefix --mode all` пишет
   `.original/.natural/.strong.wav`): предпочтение, разборчивость, артефакты
   (музыкальный шум, «подводный» тембр, потеря согласных, дыхание).
3. Записать измерения: пик и RMS речи до/после, оценка уровня шума, makeup gain,
   время обработки и xRT на целевых SoC, пик памяти, доля `Fallback*`.
4. Критерии: Natural никогда не хуже оригинала при слепом A/B на тихих записях,
   ни одного клиппинга (пик ≤ −1 дБFS), ни одного краша, fail-open подтверждён
   на сбойных входах.
5. Значения заносятся в таблицу «Android» выше.

## 12. Использование

```cpp
#include <bgmedia/vox/VoxEnhance.hpp>
using namespace bgmedia::vox;

VoxEnhanceConfig cfg;
cfg.mode = VoxEnhanceMode::Natural;
VoxCancelToken cancel;
VoxEnhanceResult r = enhanceVoice(pcm.data(), frames, {48000, 1}, cfg, &cancel);
// r.pcm всегда пригоден к отправке: либо обработанный, либо оригинал.
if (r.usedOriginal()) { /* r.report.status / r.report.detail для лога */ }
```

```sh
bgmedia_vox_enhance in.wav out/prefix --mode all
bgmedia_vox_enhance --synthetic out/prefix
```
