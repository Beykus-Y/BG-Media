# BG Vox — Lyrics (P3)

Статус: P3 «BG Vox Lyrics» из issue #82, в той же независимой библиотеке
`bgmedia_vox` (`BGMedia::Vox`). Библиотека не зависит от `bgmedia_core`, не
знает про Yandex Music, Telegram, любые провайдерские API, не ходит в сеть, не
скачивает модели и **ничего не хранит и не кэширует**.

Главное правило: **текст песни берётся у источника музыки, а не придумывается.**
Библиотека принимает текст, который хост получил законным путём (адаптер BeyGram
к источнику музыки), разбирает его, при необходимости подгоняет по времени под
звук и честно помечает, откуда взялись текст и тайминги. То, что распознано
нейросетью, никогда не выдаётся за оригинальный текст исполнителя.

## 1. Что входит в этот PR

- Публичный API `include/bgmedia/vox/VoxLyrics.hpp` (`bgmedia::vox`): типы
  `VoxLyrics` / `VoxLyricLine` / `VoxLyricsSource`, парсеры `parseLrc()` и
  `parsePlainLyrics()`, сериализатор `toLrc()`, детектор вокальных участков
  `detectVocalRegions()`, выравнивание `alignLyricsToTranscript()` /
  `alignLyricsToVocalRegions()`, `lyricsFromTranscript()`,
  `markInstrumentalGaps()`, конвейер `buildLyrics()`, хук разделения
  `IVoxVocalSeparator`.
- Реализация: `src/vox/VoxLyricsText.cpp` (LRC, UTF-8, нормализация),
  `VoxLyricsVocal.cpp` (детектор), `VoxLyricsAlign.cpp` (выравнивание и конвейер),
  `VoxLyricsCapi.cpp`.
- C ABI `include/bgmedia/vox/vox_lyrics_capi.h` для JNI/iOS.
- CLI `bgmedia_vox_lyrics` (`tools/vox_lyrics`), собирается всегда при
  `BGMEDIA_BUILD_VOX=ON`; ASR-путь (`--model`) только с `BGMEDIA_VOX_WHISPER=ON`.
- Тесты `vox_lyrics.*` (31 штука, `tests/test_vox_lyrics.cpp`), без внешних
  фикстур и моделей; синтетика музыки `makeSungMusic()` в
  `tools/support/VoxSynthetic.hpp`.

При `-DBGMEDIA_BUILD_VOX=OFF` проект собирается без изменений (проверено).

## 2. Контракт

Все точки входа `noexcept`, реентерабельны, без глобального состояния; PCM
заимствуется на время вызова (лимиты формата те же, что у P1: 8000..48000 Гц,
1..2 канала, NaN/Inf отклоняются). Любое исключение превращается в статус
(`VoxLyricsStatus`, имя через `voxLyricsStatusName()`). Отмена —
`VoxCancelToken`, прогресс — `VoxProgressFn`.

### Происхождение (provenance)

`VoxLyricsSource`, от самого надёжного к самому слабому:

| Значение | Текст | Тайминги |
|---|---|---|
| `ProviderSynced` | провайдера | провайдера (LRC от хоста) |
| `ProviderUnsynced` | провайдера | нет |
| `AlignedToAudio` | провайдера | **оценены здесь** по звуку, это не синхронизация провайдера |
| `AsrHypothesis` | **распознан моделью** | оценены ASR |

Поля `VoxLyrics`: `source` (самое слабое по строкам), `providerTag` (непрозрачная
метка хоста), `hostMayCache` (выставляет хост), `isOriginalText` (`true` только
если текст пришёл от хоста как текст провайдера; для `AsrHypothesis` всегда
`false`), `status`, `detail`.

Поля `VoxLyricLine`: `startSec`/`endSec` (< 0 неизвестно), `text`, `confidence`
(0..1, < 0 неизвестно; у провайдерских таймингов 1), `source`, `instrumental`,
`words`, `stanzaBreak` (пустая строка между куплетами), `interpolated` (время не
измерено, а выведено из соседей/вокальных участков). `isLowConfidence(порог)`
истинно и для неизвестной уверенности.

### Правила честности для UI (обязательные для хоста)

1. `AsrHypothesis` — показывать с пометкой «распознано автоматически», как
   гипотезу, не как «текст песни»; не подписывать именем исполнителя, не
   предлагать копировать/публиковать как оригинал.
2. `AlignedToAudio` — текст можно показывать как текст провайдера, но тайминги —
   оценка: не называть это «синхронизированным текстом провайдера»; строки с
   `isLowConfidence()` или `interpolated` не подсвечивать как точное караоке.
3. Никакого обещания точности на пении, полифонии, рэпе, хоре и плотных миксах.
4. Инструментальные части — явные строки `instrumental = true` с пустым текстом
   (в LRC `♪`), а не пропуски.
5. `toLrc()` для не-провайдерских источников пишет в начало файла метки
   `[x-bg-source:...]` и `[x-bg-original:0|1]`, чтобы файл сохранял пометку;
   `parseLrc()` их игнорирует (при чтении обратно пометка теряется, хост должен
   хранить её сам).

## 3. Права, провайдеры, кэширование

Библиотека не принимает юридических решений и не знает условий конкретного
провайдера. Тексты песен — охраняемый контент, а условия показа, кэширования и
хранения у провайдеров разные. Поэтому:

- решение «можно ли кэшировать/показывать/сохранять» принимает **хост**: адаптер
  BeyGram выставляет `providerTag` и `hostMayCache` по условиям провайдера;
  библиотека только переносит эти поля (в том числе через выравнивание и C ABI:
  `bgm_vox_lyrics_set_provenance`);
- библиотека **не пишет на диск и не держит текст между вызовами**; `buildLyrics()`
  возвращает результат и забывает всё;
- результат локальной обработки (выровненные тайминги, ASR-гипотеза) — производный
  от текста/аудио пользователя; можно ли его сохранять и показывать другим, тоже
  решает хост (флаг `hostMayCache` по умолчанию `false`);
- в репозитории нет Yandex Music/Telegram/сетевого кода и не будет: адаптер к
  источнику — работа BeyGram (раздел 9).

Юридическая оценка использования конкретного провайдера здесь **не проведена**
(«не проверено»).

## 4. Парсеры

### `parseLrc()`

- Метки `[mm:ss.xx]`, `[mm:ss.xxx]`, `[mm:ss]` (1..4 цифры минут), несколько меток
  в одной строке (`[00:05.00][00:30.25]Припев`).
- `[offset:±мс]`: положительное значение сдвигает текст **раньше**
  (`время = метка − offset`), как делает большинство плееров; отрицательные
  итоговые времена зажимаются в 0.
- Метаданные (`[ti:]`, `[ar:]`, `[al:]`, `[by:]`, `[x-...]` и т.п.) игнорируются.
- Расширенные пословные метки `<mm:ss.xx>` дают `words` (конец слова — начало
  следующего, у последнего — конец строки); `<` вне метки остаётся текстом.
- Результат отсортирован по времени; `endSec` = начало следующей строки с большим
  временем, у последней строки неизвестен.
- Строка только из `♪`/`♫` — `instrumental`; пустой текст с меткой — `stanzaBreak`.
- Устойчив к мусору: нет ни одной метки — `ParseError`, строки без метки
  игнорируются и считаются в `detail`; лимиты 8 МиБ и 200 000 строк (`TooLong`);
  BOM снимается, `\r\n`/`\r`/`\n` поддержаны.
- UTF-8: разбор идёт только по ASCII-разделителям, байты многобайтных символов
  не разрезаются; невалидные последовательности заменяются на U+FFFD.

### `parsePlainLyrics()`

Одна строка текста — одна `VoxLyricLine`; пробелы схлопываются; пустые строки
сохраняются как строки с `stanzaBreak = true` (подряд идущие схлопываются, в
начале и конце отбрасываются).

## 5. Конвейер без готовых таймингов

```
вокальные участки  ->  (опционально) разделение вокал/аккомпанемент
                   ->  ASR  ->  выравнивание строк и слов по времени
```

`buildLyrics(provided, backend, separator, pcm, ...)`:

| Вход | Что делается |
|---|---|
| текст провайдера с таймингами (LRC) | `parseLrc`, возвращается как есть (PCM не нужен) |
| текст без таймингов + ASR-бэкенд | [separator] → `detectVocalRegions` → `transcribe()` (P2, пословные времена) → `alignLyricsToTranscript`; при сбое ASR или выравнивания — откат на `alignLyricsToVocalRegions` (причина в `detail`) |
| текст без таймингов, без бэкенда | `detectVocalRegions` → `alignLyricsToVocalRegions` |
| нет текста + бэкенд | `lyricsFromTranscript` — `AsrHypothesis`, `isOriginalText = false` |
| нет текста, нет бэкенда | `NoLyrics` |

После выравнивания/гипотезы `markInstrumentalGaps()` добавляет строки
`instrumental = true` для промежутков между вокальными участками длиннее
`instrumentalGapSeconds` (по умолчанию 8 с, включая вступление и концовку), если
в промежутке не начинается строка текста.

### 5.1. Детектор вокальных участков (эвристика)

`detectVocalRegions()` — **не** речевой VAD из P1/P2. Чистый DSP без модели:
кадр 64 мс, шаг 20 мс, ресемплинг в 16 кГц, KissFFT (`bgvox_`-префикс, уже
собирается в `bgmedia_vox`).

1. Доля энергии в полосе 200–4000 Гц от полной (низ ударных/баса отсекается).
2. Гармоничность: нормированный пик автокорреляции полосно-ограниченного кадра
   на лагах 80–1000 Гц (через спектр мощности, с поправкой на окно Ханна).
3. Уровневый ворота: кадр тише громких на `levelGateDb` (35 дБ) не может быть
   вокалом.
4. Оценка = гармоничность × рампа доли энергии; медиана по 5 кадрам; гистерезис
   (вкл 0.50, выкл 0.35); слияние пауз < 0.5 с; отбрасывание участков < 0.6 с.

Честно: работает на чистом ведущем вокале поверх редкой подложки; **ненадёжен**
на плотных миксах и на любом гармоническом материале в диапазоне голоса (фортепиано,
гитара, струнные, синтезаторные пэды, хор), на шёпоте и рэпе. Разделения источников
нет. Результат — подсказка, а не истина.

### 5.2. Выравнивание по транскрипту

`alignLyricsToTranscript(unsynced, asr)`:

- токены: нижний регистр (латиница, латиница-1/A, кириллица, `ё` = `е`), без
  пунктуации и апострофов (`don't` = `dont`);
- semi-global Needleman–Wunsch: ведущие и хвостовые лишние слова ASR (болтовня,
  аплодисменты) бесплатны, остальные пропуски штрафуются; совпадение — только если
  токены похожи: слова до 3 букв — точное равенство, 4 — ≥ 0.74, длиннее —
  ≥ 0.6 (1 − Левенштейн/длина);
- у строки берётся крупнейший временной кластер совпадений (случайное далёкое
  совпадение отбрасывается);
- время строки = от первого до последнего совпавшего слова ASR; слова строки
  получают текст из текста провайдера и время из ASR, потерянные слова
  интерполируются внутри строки;
- `confidence` строки = доля найденных слов; строка с долей < `minLineMatch`
  (0.34) не считается якорем: её время интерполируется между соседними якорями,
  `interpolated = true`, уверенность ≤ 0.25 (то есть «низкая»);
- вступительные/хвостовые строки без якоря ставятся по медианной длительности
  слова, не выходя за `audioSeconds`;
- нет ни одного якоря — `AlignmentFailed`, строки возвращаются без времени;
- без пословных времён сегмент делится на слова пропорционально числу символов;
- матрица ограничена (`maxMatrixCells`, `TooLong`), отмена проверяется по строкам.

`isOriginalText` остаётся как у входного текста (текст провайдера), `source`
становится `AlignedToAudio`.

### 5.3. Откат без ASR

`alignLyricsToVocalRegions()` раскладывает строки по вокальным участкам
пропорционально числу гласных (ru/en; без гласных — символы/3). Это грубая
оценка: `confidence ≤ 0.3`, `interpolated = true`. Строка не пересекает
инструментальный промежуток.

### 5.4. Хук разделения

`IVoxVocalSeparator` — только интерфейс (моно float in → вокальная дорожка той же
длины); реализации в репозитории нет. Если он передан в `buildLyrics()`,
детектор и ASR работают по вокальной дорожке; при сбое используется исходный микс
(это пишется в `detail`).

## 6. Заметки об исследовании (не реализовано)

Кандидаты на разделение вокала/аккомпанемента. Всё ниже — из общих знаний и **не
проверено** в этом репозитории (скорость на телефоне, размеры весов, лицензии
конкретных чекпоинтов нужно смотреть у каждой модели отдельно):

- **Demucs (hybrid transformer, htdemucs)** — код MIT; тяжёлый (десятки–сотни МБ
  весов, заметное время на CPU телефона), лицензии весов и обучающих данных
  «не проверено».
- **Spleeter (Deezer)** — код MIT, легче Demucs, качество ниже; конкретные
  размеры/скорость на устройстве «не проверено».
- **UVR / MDX-Net** — набор сообществом обученных моделей, лицензии разных весов
  различаются, часть может быть некоммерческой; «не проверено».

Выбор модели — задача хоста/BeyGram (размер приложения, батарея, лицензия весов);
хук оставлен, чтобы адаптер можно было добавить без изменения ядра.

ASR на пении: whisper-подобные модели обучены в основном на речи; на пении
типичны ошибки на растянутых гласных, вибрато, бэк-вокале, наложении
аккомпанемента, галлюцинации на инструментале и повторах. Пословные времена на
пении менее надёжны, чем на речи. Точность на пении **не измерялась и не
обещается**. Поэтому основной сценарий — готовый текст провайдера, а ASR служит
только для подгонки его тайминга; транскрипт без текста — гипотеза.

## 7. Что измерено, а что нет

Измерено на синтетике (`makeSungMusic`: «поющий» гармонический тон с вибрато 5.5 Гц
над ударной подложкой 120 bpm с бочкой 55 Гц, шумовыми малым и хэтом; два участка
по 6 с, 24 с, 44.1 кГц; без внешних файлов), 6 сидов на строку:

| голос относительно подложки (RMS) | участки найдены ±0.3 с | худшая ошибка границы | ложные участки на подложке без голоса |
|---|---|---|---|
| +6 дБ | 6/6 | 0.04 с | 0 |
| 0 дБ | 6/6 | 0.08 с | 0 |
| −6 дБ | 6/6 | 0.12 с | 0 |
| −9 дБ | 6/6 | 0.14 с | 0 |
| −12 дБ | 6/6 | 0.16 с | 0 |
| **подложка с гармоническим пэдом** (аккорд из трёх пил в диапазоне голоса), любой уровень | **0/6** | — | **6 из 6** (весь трек считается вокалом) |

Последняя строка — известный предел: эвристика по гармоничности не отличает
устойчивый гармонический инструмент от голоса (тест
`vox_lyrics.vocal_detect_known_limit_harmonic_pad` печатает эти цифры и
намеренно ничего не утверждает). Остальные тесты проверяют LRC (метки, offset,
расширенные слова, мусор, UTF-8), DP-выравнивание на русском и английском с
ошибками/пропусками/лишними словами, интерполяцию, низкую уверенность,
`AsrHypothesis ≠ оригинал`, инструментальные промежутки, отмену, `buildLyrics()`
с поддельным ASR-бэкендом и C ABI.

**Не проверено:** любое реальное аудио (песни, живой вокал, рэп, хор, другие
языки), реальный whisper на пении, выравнивание на реальных ошибках ASR, скорость
и память на Android, поведение при полифонии, юридическая сторона провайдеров и
весов моделей. Тесты доказывают корректность логики на синтетике, а не качество
на музыке.

## 8. Потоки, память

Вызовы реентерабельны, состояния нет. Память: детектор — моно-копия входа (и
16 кГц-копия при другой частоте) плюс несколько векторов по числу кадров;
выравнивание — матрица `N × M` байт путей (до `maxMatrixCells`, по умолчанию 16
млн ≈ 16 МБ). Один объект C ABI не потокобезопасен (один дескриптор на поток).

## 9. Что остаётся для BeyGram

- Адаптер к источнику музыки: запрос текста/синхронизации **законными средствами и
  в рамках условий провайдера**, выставление `providerTag` и `hostMayCache`.
- Решение о показе, хранении, кэше и срок жизни текста; юридическая проверка.
- UI: пометки «распознано автоматически» для `AsrHypothesis`, «тайминги
  приблизительные» для `AlignedToAudio`, показ строк с низкой уверенностью без
  караоке-подсветки, инструментальные части.
- Караоке-подсветка по словам (`VoxLyricLine::words`), синхронизация с плеером.
- Загрузка/хранение модели ASR и (если нужно) модели разделения.
- Замеры на реальных треках и устройствах.

## 10. Использование

```cpp
using namespace bgmedia::vox;
VoxProvidedLyrics p;
p.text = textFromMusicSource;      // от адаптера хоста
p.synced = false;                  // true, если это LRC
p.providerTag = "adapter-name";    // метка хоста
p.hostMayCache = adapterSaysMayCache;

VoxBuildOptions o;                 // o.asr.language = "ru"
VoxLyrics l = buildLyrics(p, backendOrNull, nullptr, pcm, frames, {44100, 2}, o);
if (l.status == VoxLyricsStatus::Ok) {
    for (const VoxLyricLine& line : l.lines) { /* line.isLowConfidence(), line.instrumental */ }
}
```

CLI:

```
bgmedia_vox_lyrics song.wav --lyrics text.txt [--out out.lrc] [--json out.json] [--gap 8]
bgmedia_vox_lyrics song.wav --lrc file.lrc          # печать как есть
bgmedia_vox_lyrics song.wav --lyrics text.txt --model ggml-base.bin --lang ru   # с BGMEDIA_VOX_WHISPER=ON
```
