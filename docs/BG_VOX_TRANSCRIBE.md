# BG Vox — Transcribe MVP (P2)

Статус: P2 «BG Vox Transcribe» из issue #82. Распознавание речи (ASR) в той же
независимой библиотеке `bgmedia_vox` (`BGMedia::Vox`). Библиотека не зависит от
`bgmedia_core`, не знает про Telegram/TDLib, микрофон, Opus и UI, не ходит в
сеть и **не скачивает модели**.

Главное правило этого PR: **машинный текст никогда не выдаётся за надёжную
копию сказанного.** `VoxTranscript::machineGenerated` всегда `true`, у каждого
сегмента есть `confidence` (0..1, отрицательное = неизвестно) и флаг
`lowConfidence`. Хост обязан помечать текст как распознанный автоматически и
держать оригинал звука доступным.

## 1. Что входит в этот PR

- Публичный C++ API `include/bgmedia/vox/VoxTranscribe.hpp`: `transcribe()`
  (`noexcept`, float и int16), статусы, опции, сегменты/слова, абстрактный
  бэкенд `IVoxAsrBackend`.
- Frontend `src/vox/VoxTranscribe.cpp`: валидация формата, downmix в моно,
  **полосно-ограниченный ресемплинг** в частоту бэкенда
  (`src/vox/VoxResample.{hpp,cpp}`), нарезка длинного аудио по паузам, сдвиг и
  зажим таймкодов, дедупликация перекрытий, флаг низкой уверенности, отмена и
  прогресс.
- C ABI `include/bgmedia/vox/vox_transcribe_capi.h` (+
  `src/vox/VoxTranscribeCapi.cpp`) для будущих JNI/iOS-хостов.
- **Опциональный** адаптер whisper.cpp: `include/bgmedia/vox/VoxWhisper.hpp`
  (ставится из `adapters/vox_whisper/`), опция CMake `BGMEDIA_VOX_WHISPER`
  (по умолчанию `OFF`). Тяжёлая зависимость по умолчанию не собирается и не
  поставляется.
- CLI `bgmedia_vox_transcribe` (только при `BGMEDIA_VOX_WHISPER=ON`).
- Unit-тесты `vox_transcribe.*` на синтетике и **фейковом** бэкенде: модель для
  тестов не нужна.

Сборка:

```sh
cmake -S . -B build -DBGMEDIA_BUILD_VOX=ON                      # ядро, без ASR
cmake -S . -B build -DBGMEDIA_BUILD_VOX=ON -DBGMEDIA_VOX_WHISPER=ON
```

При `BGMEDIA_VOX_WHISPER=ON` берётся установленный пакет
(`find_package(whisper CONFIG)`), иначе `FetchContent` тянет
`https://github.com/ggml-org/whisper.cpp` на **фиксированном теге v1.9.5**
(`cmake/FindOrFetchWhisper.cmake`, `GGML_NATIVE=OFF`, чтобы бинарник не был
заточен под CPU машины сборки; для локальной сборки можно передать
`-DGGML_NATIVE=ON`). При `-DBGMEDIA_BUILD_VOX=OFF` проект собирается как раньше.

## 2. Контракт в одном абзаце

`transcribe(backend, pcm, frames, format, options, cancel, progress)` —
`noexcept`, re-entrant, без глобального состояния. Вход: interleaved PCM
(`float` в [-1, 1] или `int16`, конвертация `x / 32768`), 8000–48000 Гц, 1–2
канала (те же пределы, что у P1). Буфер принадлежит вызывающему на время
вызова. Результат — один `VoxTranscript`: сегменты с таймкодами **на шкале
записи**, язык, имя бэкенда и модели, статус, длительность и время обработки.
Любая проблема — это статус, а не исключение: функция ловит всё, включая
исключения бэкенда.

| Статус | Когда |
|--------|-------|
| `Ok` | дошли до конца (в том числе «речи нет» → 0 сегментов) |
| `Cancelled` | отмена; `segments` содержит завершённые чанки |
| `InvalidInput` | null/0 кадров, NaN/Inf, неположительный `maxDurationSeconds` |
| `UnsupportedFormat` | частота вне 8000–48000 или каналов не 1–2 |
| `TooLong` | длиннее `maxDurationSeconds` (по умолчанию 1800 с) |
| `NoBackend` | `backend == nullptr` или адаптер не собран |
| `ModelUnavailable` | файла модели нет / он битый / формат не поддержан |
| `BackendError` | бэкенд сообщил об ошибке (`detail` — его текст) |
| `OutOfMemory` | `std::bad_alloc` (в т.ч. из бэкенда) |
| `InternalError` | неожидаемое исключение |

При любом статусе, кроме `Ok`, уже полученные сегменты сохраняются — это
**частичный** результат, и хост обязан показать его как частичный (или не
показывать вовсе), а не как готовый текст.

## 3. Потоки, владение, отмена, память

1. Вызов — в рабочем потоке, никогда в capture/audio callback. Аллокации и
   inference внутри; реального времени здесь не обещается.
2. Один экземпляр бэкенда **не обязан** быть thread-safe: хост либо
   сериализует вызовы, либо создаёт по экземпляру на поток (каждый экземпляр
   держит свою копию модели в памяти). В C ABI вызовы на одном handle
   сериализуются мьютексом внутри.
3. Модель грузится один раз (`createWhisperBackend`) и переиспользуется для
   многих сообщений; освобождение памяти модели = удаление бэкенда.
4. Отмена — `VoxCancelToken` (тот же класс, что в P1; поддерживает внешний
   `volatile int*` для C ABI). Опрашивается между чанками, внутри ресемплера и
   передаётся в бэкенд (у whisper — через `abort_callback`).
5. Прогресс — `VoxProgressFn`, из вызывающего потока, примерно каждые 5 % и
   один раз на 1.0; у whisper поверх ещё и его `progress_callback` внутри чанка.
6. Память: `frames` float на моно + копия после ресемплинга (≈ `16000 *
   секунды` float) + память модели. Потребности модели библиотека **сообщает**
   (`IVoxAsrBackend::info()` → `modelFileBytes`, `approxRamBytes`; в C ABI —
   `bgm_vox_asr_info`), но скачивать/удалять модели — дело хоста.
7. Скачивание, проверка и удаление файлов модели — целиком хост. Библиотека
   только читает путь, который ей дали, и никогда не обращается к сети.

## 4. Ресемплинг (почему именно так)

Бэкенды хотят 16 кГц моно. Прошлое ревью в этом репозитории уже указывало на
ресемплер без фильтра как на баг: простая децимация 48к→16к складывает всё
выше 8 кГц обратно в слышимый диапазон (7 кГц уезжает в 1 кГц и портит признаки
для ASR). Поэтому `detail::resampleMono()` — polyphase windowed-sinc с окном
Кайзера (стоп-полоса ≈ 80 дБ): ФНЧ ставится на 0.95 от **меньшей** из двух
частот Найквиста, сумма коэффициентов каждой фазы нормирована (усиление по DC
ровно 1), ядро симметрично (групповая задержка 0, выходной сэмпл `n`
соответствует входному времени `n * inRate / outRate`). Тесты:

- тон 1 кГц при 48к→16к проходит в пределах 0.5 дБ (и 3 кГц при 44.1к→16к);
- тоны 9, 10, 12 кГц при 48к→16к ослаблены более чем на 40 дБ;
- при 8к→16к образ 1 кГц на 7 кГц ослаблен более чем на 40 дБ;
- длина выхода = `floor(frames * outRate / inRate)`, DC-усиление 1,
  `inRate == outRate` — побитовая копия.

## 5. Нарезка на чанки

Модели whisper работают окнами 30 с, длинное сообщение надо резать, и резать
**не посреди слова**. Алгоритм: по моно-сигналу 16 кГц считаются кадры 10 мс
(`detail::frameMeanSquareDb`) и запускается VAD из P1 (`detail::runVad`, без
hangover). Далее для каждого чанка во **второй половине** окна
`options.chunkSeconds` (по умолчанию 30 с, зажимается в 2..600 с) ищется самая
тихая пауза длиной ≥ 80 мс и рез делается по её середине. Если паузы нет
(непрерывная речь), рез жёсткий по границе окна, но следующий чанк берётся с
перекрытием 0.5 с, а сегменты, середина которых попала в перекрытие,
выбрасываются с одной из сторон — дубликатов в выводе нет.

Дополнительно: чанки без речевой активности (< 50 мс активных кадров) бэкенду
не отдаются вовсе — это дешевле и не даёт модели «галлюцинировать» текст из
тишины. Полностью тихий или слишком тихий вход → `Ok` с нулём сегментов и
**без единого вызова бэкенда**.

Таймкоды бэкенда (относительные к чанку) сдвигаются на начало чанка, зажимаются
в [0, длительность записи], сегменты с пустым текстом отбрасываются, список
сортируется по времени (stable).

## 6. Язык

`options.language` пуст → автоопределение: первый чанк с речью отдаётся
бэкенду в режиме auto, определённый язык фиксируется и передаётся в остальные
чанки (`detectedLanguage`), чтобы длинное сообщение не «перескакивало» между
языками. Непустой `language` (`"ru"`, `"en"`, `"pt-BR"` — используется только
первый сабтег) принудительно задаёт язык. `translateToEnglish` работает только
если бэкенд это умеет (`VoxAsrBackendInfo::supportsTranslation`).

## 7. Уверенность и честность текста

- whisper: `confidence` сегмента = средняя вероятность его текстовых токенов
  (специальные и timestamp-токены исключены), слова (при `wordTimestamps`) —
  средняя вероятность токенов слова.
- `lowConfidence = true`, если `confidence < options.lowConfidenceThreshold`
  (по умолчанию 0.5) **или** уверенность неизвестна (`< 0`). Неизвестная
  уверенность никогда не считается хорошей.
- `machineGenerated` — всегда `true`; в C ABI
  `bgm_vox_transcript_machine_generated()` возвращает 1 всегда.
- Средняя вероятность токенов — это уверенность **модели**, а не вероятность
  того, что текст верен. На шумной записи модель бывает уверенно неправа.
  Поэтому: хост показывает «машинный текст», даёт слушать оригинал и не
  подменяет им голосовое сообщение.

## 8. Аудит: whisper.cpp vs sherpa-onnx

| Критерий | whisper.cpp | sherpa-onnx |
|----------|-------------|-------------|
| Лицензия кода | MIT | Apache-2.0 |
| Движок | собственный ggml (C/C++), без внешнего рантайма | ONNX Runtime |
| Режим | офлайн по файлу/буферу; «стриминг» в примерах — скользящее окно, не настоящий streaming ASR | офлайн **и** настоящий streaming (streaming zipformer transducer) |
| Русский | да, мультиязычные модели (`ggml-tiny/base/small/medium/large`, 99 языков); варианты `*.en` — только английский | да, но нужен конкретный экспорт модели: в зоопарке моделей k2-fsa есть русские варианты (экспорты GigaAM, модели на базе Vosk). Конкретные модели и их качество — **не проверено** |
| Качество на русских голосовых | tiny/base — слабо, small/medium — заметно лучше (общее знание, **на реальных голосовых BeyGram не проверено**) | **не проверено** |
| Размер моделей | ggml: tiny ≈ 75 МБ, base ≈ 142 МБ, small ≈ 466 МБ, medium ≈ 1.5 ГБ, large ≈ 3 ГБ; квантованные (q5_0/q8_0) существенно меньше | зависит от модели; streaming zipformer-модели обычно десятки–сотни МБ, точные цифры — **не проверено** |
| RAM | примерно «файл модели + рабочие буферы»; `info()` отдаёт оценку (файл × 1.2 + 256 МБ), это **оценка, а не измерение** | **не проверено** |
| CPU / SIMD | AVX/AVX2/F16C на x64, **NEON** на ARM64, OpenMP; опционально Core ML, OpenVINO, CUDA, Vulkan | NEON на ARM64 и x64-SIMD через ONNX Runtime; сборки для Android/iOS есть |
| Платформы | x64, ARM64, Android/iOS, WASM | x64, ARM64, Android/iOS, WASM |
| Зависимости в сборке | только ggml (вендорится самим whisper.cpp) | ONNX Runtime (внешняя библиотека) |
| Пунктуация/таймкоды слов | таймкоды сегментов всегда, токенов — опционально (`token_timestamps`); пунктуация есть в выводе модели | таймкоды и опциональные модели пунктуации/VAD/диаризации в наборе |

Почему первым адаптером выбран **whisper.cpp**:

1. MIT и одна самодостаточная зависимость (ggml вендорится внутри), без
   внешнего рантайма — проще собрать под Android/iOS и проще аудировать.
2. Мультиязычность «из коробки» одной моделью, включая русский, и готовое
   автоопределение языка — ровно то, что нужно для голосовых сообщений.
3. Есть всё, что требует контракт: `abort_callback` (отмена),
   `progress_callback`, вероятности токенов (уверенность), таймкоды.
4. Для P2 нужен **офлайн** разбор уже записанного сообщения; настоящий
   streaming не требуется.

**sherpa-onnx — планируемый второй адаптер**, именно для streaming-сценария
(распознавание во время записи/воспроизведения) и как альтернатива там, где
whisper слишком тяжёл. Интерфейс `IVoxAsrBackend` для этого уже достаточен для
офлайн-режима; для настоящего streaming понадобится отдельный интерфейс
(push-PCM + частичные результаты), его в этом PR нет.

## 9. Что остаётся для BeyGram

Исходники BeyGram в этом репозитории недоступны, поэтому ниже — требования к
хосту, а не описание сделанного:

1. Кнопка «Распознать» у голосового сообщения — **по запросу**, никакого
   массового фонового распознавания всех сообщений.
2. UX скачивания модели: выбор размера (tiny/base/small), показ размера файла и
   оценки RAM (`bgm_vox_asr_info`), докачка/отмена, удаление модели, работа
   только по Wi-Fi по желанию пользователя. Скачивание — код хоста.
3. Согласие: явное предупреждение, что распознаёт модель **на устройстве**
   (ничего не уходит в сеть библиотекой), и что текст машинный.
4. Отображение: подпись «машинный текст», визуальное отличие сегментов с
   `lowConfidence`, доступ к оригинальному аудио, запрет пересылки распознанного
   текста как «расшифровки» без пометки.
5. Частичный результат при `Cancelled`/ошибке помечается как неполный.
6. Поток: загрузка модели и распознавание — в рабочем потоке с прогрессом и
   кнопкой отмены; на слабых устройствах — предупреждение о времени.

## 10. Измерения

### Десктоп, синтетика (`vox_transcribe.*`, фейковый бэкенд)

Проверено в unit-тестах (Release, GCC, Linux x86-64): качество ресемплера
(раздел 4), границы чанков только в паузах, непревышение `chunkSeconds`,
сдвиг/зажим таймкодов, дедупликация перекрытий, отмена с частичным
результатом, проброс ошибок бэкенда, перехват исключений, идентичность путей
`int16` и `float`, флаг `lowConfidence`, `fullText()`.

### Реальная модель whisper — не прогнано

Адаптер **собран** (`-DBGMEDIA_VOX_WHISPER=ON`, whisper.cpp v1.9.5 через
FetchContent, Linux x86-64, CPU) и путь ошибки `ModelUnavailable` проверен на
битом файле модели (whisper сообщает `invalid model data (bad magic)`,
`createWhisperBackend` возвращает `nullptr` со статусом `ModelUnavailable`).
Настоящая расшифровка **не выполнялась**: скачивание `ggml-tiny.bin` с
huggingface.co в этой среде заблокировано (прокси отдаёт 403), TTS
(`espeak-ng`/`espeak`) недоступен и не устанавливается. Цифр (время, xRT,
текст) здесь поэтому нет — вместо них ничего, выдуманные значения в документ не
вносятся.

## 11. Что не проверено

- Реальные RAM/CPU/время на Android ARM64 — **не проверено** (нет устройства в
  CI); `approxRamBytes` — оценка по размеру файла модели, не измерение.
- Точность на реальных русских голосовых сообщениях (шум, улица, гарнитура,
  быстрая речь, мат и сленг) — **не проверено**.
- sherpa-onnx целиком: конкретные русские модели, их размеры, скорость и
  качество — **не проверено**, в коде этого PR его нет.
- Поведение whisper на очень коротких (< 1 с) сообщениях: чанк добивается
  тишиной до 1 с (таймкоды потом зажимаются), на реальной речи не измерено.
- Качество `wordTimestamps` у whisper (экспериментальная функция апстрима).
- GPU-путь (`useGpu`) не собирался и не тестировался.

## 12. Использование

```cpp
#include <bgmedia/vox/VoxTranscribe.hpp>
#include <bgmedia/vox/VoxWhisper.hpp>   // только с BGMEDIA_VOX_WHISPER=ON
using namespace bgmedia::vox;

std::string error;
VoxTranscribeStatus status{};
auto backend = createWhisperBackend({"/data/models/ggml-base.bin"}, &error, &status);
if (!backend) { /* status == ModelUnavailable: предложить скачать модель */ }

VoxTranscribeOptions options;
options.language = "ru";          // пусто = автоопределение
VoxCancelToken cancel;            // cancel.cancel() из UI-потока
VoxTranscript t = transcribe(backend.get(), pcm.data(), frames, {48000, 1},
                             options, &cancel,
                             [](float f) { /* прогресс 0..1 */ });
if (t.status == VoxTranscribeStatus::Ok) {
    for (const VoxSegment& s : t.segments) {
        // s.startSec, s.endSec, s.text, s.confidence, s.lowConfidence
    }
}
// t.machineGenerated == true: показывать как машинный текст, не как оригинал.
```

C ABI (JNI/iOS):

```c
bgm_vox_asr* asr = NULL;
char err[256];
if (bgm_vox_whisper_create(path_utf8, 0, 0, &asr, err, sizeof err) == BGM_VOX_TR_OK) {
    bgm_vox_transcript* r = NULL;
    volatile int cancel = 0;
    int st = bgm_vox_transcribe_s16(asr, pcm, frames, 48000, 1, "ru", 0, 0, 0,
                                    &cancel, on_progress, user, &r);
    for (size_t i = 0; i < bgm_vox_transcript_segment_count(r); ++i) { /* ... */ }
    bgm_vox_transcript_free(r);
    bgm_vox_asr_free(asr);
}
```

